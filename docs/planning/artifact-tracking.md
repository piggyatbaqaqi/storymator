# Tracking ComfyUI artifacts

*2026-09-09. Written because a blanket `output/ user/` ignore was added
to `.gitignore` and it undid a deliberate choice: the ComfyUI
environment was set up to point its output and user directories into
this repository **so that artifacts could be tracked**. That goal is
right. The blanket rule was wrong. So was removing the rule entirely.
This is the version that does what was intended.*

## The principle

**Ignore by what wrote it, not by which directory it is in.**

A file that records a decision you made is an artifact. A file ComfyUI
wrote on its own is state. `user/` contains both, mixed together, which
is why a directory-level rule cannot be right in either direction.

## What is actually in `user/` — measured

| path | bytes | what it is | tracked |
|---|---:|---|---|
| `__manager/cache/*.json` | **17 MB** | registry snapshots ComfyUI Manager downloads; refreshed on a timer. 11 MB sits in one file, `881334633_nodes.json`. | no |
| `comfyui.db` | 148 KB | SQLite. Binary, rewritten whole, cannot be diffed or merged, and is open while ComfyUI runs — a commit can capture a torn snapshot. | no |
| `comfyui.db.lock` | — | a live lock file. Checking out an old commit can leave a stale one behind. | no |
| `comfyui*.log` | 44 KB | rotating logs. Rotation moves content between files, so a rotation alone produces a large diff carrying no information. | no |
| `default/workflows/*.json` | **40 KB** | **the workflows.** Hand-built, JSON, diffable. | **yes** |
| `default/comfy.settings.json` | **4 KB** | **your interface and configuration choices.** | **yes** |

**44 KB of the 17 MB carries intent — 0.25 %.** Tracking `user/`
wholesale commits 17 MB of re-downloadable cache in order to preserve
44 KB of decisions, and buries the 44 KB in the noise of the 17 MB.

The `.gitignore` rule therefore inverts: ignore `user/*`, then
re-include `default/workflows/` and `default/comfy.settings.json`.
They are tracked **in place**, where ComfyUI already reads and writes
them, so there is no copy step to forget and no second copy to drift.

## Why `output/` is different

`output/` is 17 MB in 13 images — 1024×1024 PNGs at roughly 1.3 MB
each, from light use over three weeks.

Three properties make git the wrong store for them:

1. **No compression to gain.** PNG is already deflate-compressed, so
   git's zlib pass buys almost nothing. Every image is a full blob.
2. **Every version is permanent.** Deleting a file does not shrink the
   repository. Recovering the space needs `git filter-repo` and a
   force-push, which invalidates every existing clone. This is the one
   genuinely irreversible mistake available here.
3. **Hosting limits are real.** GitHub warns at 50 MB per file and
   blocks at 100 MB, with soft repository limits in the low gigabytes.

And the decisive one:

4. **Git adds no provenance you do not already have.** ComfyUI writes
   the full generation graph into each PNG. Verified on
   `output/ComfyUI_00001_.png`: a `prompt` chunk of 1 977 characters
   and a `workflow` chunk of 7 305 characters, both JSON. The workflow
   that made an image travels *inside* the image. Git would add a
   timestamp and nothing else.

What git cannot supply, and what is actually missing, is **why you kept
this one** — a human judgement, not a file property.

## Recording intent

Committing `user/` wholesale records *state*, not intent. A commit
saying "`comfyui.db` changed, two logs rotated, 11 MB of cache
refreshed" describes something you did not decide, and you cannot write
a truthful message for it. The SKOL history is the counter-example
worth copying: every message there says what was learned or chosen.

Two mechanisms, one per kind of artifact:

**Workflows and settings — the commit message.** They are tracked in
place, so a ComfyUI save shows up as a modification and you commit when
you have decided something is worth keeping. The message carries the
intent, exactly as in SKOL. Saves you did not mean to keep simply stay
uncommitted.

**Outputs — a manifest row.** One append-only file, `output/MANIFEST.tsv`,
tracked in git while the images are not:

```
sha256  file  timestamp  model  seed  workflow  note
```

Every field except `note` is generated by reading the PNG's own
metadata chunks, so the manifest can be rebuilt from the images at any
time. `note` is typed by you and is the whole point: an image with a
note was kept on purpose; an image without one was a throwaway. The
manifest is small, diffable, greppable and reviewable in a way a
directory of PNGs is not.

## Disaster recovery

| # | Disaster | Response | Recovery time |
|---|---|---|---|
| D1 | A workflow is edited into uselessness | `git checkout` the previous revision from `user/default/workflows/` | seconds |
| D2 | ComfyUI's `user/` state is corrupted — bad update, database corruption | **Rebuild, do not restore.** It is derived: delete `__manager/cache/` and `comfyui.db`, restart, ComfyUI re-downloads and rebuilds. Workflows and settings return from git. | minutes |
| D3 | A bad ComfyUI upgrade breaks the environment silently, and the breakage gets committed | Nightly `tar` of `user/` into a dated archive outside the repo, keeping *N* days. This is the case git cannot cover, because you would have committed the damage. | minutes |
| D4 | The box dies | The git remote holds everything irreplaceable: workflows, settings, code, manifest. Images restore from the backup target. | hours |
| D5 | An image must be regenerated months later | The workflow is in git *and* embedded in the PNG; the manifest carries model and seed. | minutes |
| D6 | The repository becomes too large to clone | **Prevented, not recovered** — this is why `output/` stays out. There is no cheap fix after the fact. | n/a |

**Where the bytes go.** Settled 2026-09-09:
`piggy@skol:/backups/puchpuchobs/home/piggy/lab/storymator`, written by
[`bin/backup-storymator`](../../bin/backup-storymator) from cron on
puchpuchobs. `/backups` on skol is a 4.6 TB volume with 1.8 TB free.

The script rotates **by distinct state rather than by day**: each
archive is built reproducibly and discarded when its hash matches the
newest one already stored, so an idle week costs nothing and `--keep 30`
means the last thirty times something actually changed.

*When to stop using tarballs.* Each run stores a full copy of whatever
changed, so the scheme is right while an archive is small (15 MB today)
and wrong once one is large. **The trigger is a single archive passing
roughly 1 GB.** At that point switch to `restic`, which is already
installed on puchpuchobs and needs only sftp at the far end:

```sh
restic -r sftp:piggy@skol:/backups/.../storymator/restic init
restic -r ... backup output user --exclude 'user/__manager/cache'
restic -r ... forget --keep-daily 7 --keep-weekly 4 --keep-monthly 6 --prune
```

It deduplicates, so a nightly run costs only the new images. Unattended
use needs `--password-file`.

If images must instead live inside git's workflow, Git LFS is the
fallback — familiar commands, blobs out of the pack, at the cost of an
LFS quota. It postpones D6 rather than solving it.

## Summary of the rule

* Track what you decided: `user/default/workflows/`,
  `user/default/comfy.settings.json`.
* Ignore what ComfyUI decided: the manager cache, the database, the
  lock, the logs.
* Keep `output/` bytes out of git; track `output/MANIFEST.tsv` instead,
  and back the bytes up somewhere that is designed to hold them.
