# Tools this repository's own development needs.  Nothing here ships.
#
# The boundary that matters
# -------------------------
# A ComfyUI custom node pack's requirements.txt is installed into every
# user's ComfyUI by the Manager, so it carries runtime dependencies and
# nothing else.  comfyui_acme/requirements.txt is deliberately down to a
# single line for that reason.  comfyui_penciltest will be tighter still,
# because it is meant to be contributed upstream.
#
# So development tooling goes here instead, at the top level, where it is
# installed by whoever works on the repository and by nobody else.
#
# Runtime libraries are NOT listed here
# -------------------------------------
# numpy, scipy, Pillow and OpenCV are supplied by the `storymator` conda
# environment and, for the node packs, by ComfyUI itself.  Listing them
# would invite someone to `pip install -r` their way into a second,
# conflicting set.  See the note on the environment below.

# Testing.  pytest.ini lives per component -- big_green_button/ and
# comfyui_acme/ each have their own -- so there is no top-level config
# to match this.
pytest

# Type checking and style, both required by CLAUDE.md for new code.
# Neither has a configuration file anywhere in the repository yet, so
# "passes mypy" currently means "passes whatever mypy is on the path,
# with its defaults".  Worth fixing; see docs/README.md.
mypy
flake8

# Needed to TEST comfyui_acme, not to ship it.
#
# comfyui_acme/nodes/_convert.py imports torch, and inside ComfyUI that
# is already present -- which is why the pack's own requirements.txt
# does not name it, exactly as it does not name numpy.  But running
# comfyui_acme/tests/test_nodes.py outside ComfyUI needs it in this
# interpreter, and without it those 32 tests SKIP rather than fail.
# A silent 32-test hole is the thing this file exists to prevent.
#
# The environment this was captured from carries a CUDA build
# (2.13.0+cu130) installed from PyTorch's own index.  Unpinned here
# because the right wheel depends on the machine; a CPU build is enough
# for the tests.
torch

# Reads docs/bibliography.bib.
#
# Pinned to the 2.x line on purpose: v1 and v2 are different libraries
# wearing one name.  v1 is `bibtexparser.load(fh)` returning objects with
# an ENTRYTYPE key; v2 is `bibtexparser.parse_file(path)` returning a
# Library with .entries, .failed_blocks and typed fields.  Code written
# against one raises AttributeError on the other.
bibtexparser>=2.0.0b9
